## 1. 目标

把 Phase 0.5-A 的 Claude 单 Agent 闭环，扩成 **三个 Agent 的统一控制面**，保持每个 Agent 的能力差异，不做「所有 Agent 都一样」的假设。

0.5-B 完成时，同一个 daemon 应当能：

1. 派发任务给 claude / codex / pi 任一 Agent，拿回同构的 `SessionRef`；
2. 对任一 Agent 读 transcript（统一消息模型、字节偏移游标）；
3. 按各 Agent 的 `SessionCaps` 决定 inject / interrupt / handoff 是否可用，不可用就**不暴露**（API 422 + 工具不注册）；
4. 对任一 Agent 至少有一条经过实测的 handoff 或 resume 路径；
5. 事件归一化后统一渲染，未知事件不导致 daemon 崩溃；
6. Claude 的 0.5-A 行为零回归。

## 2. 非目标

- Web UI、DSH、跨 Agent 会话搬家、跨 Agent 记忆同步（门禁文档 §4 已列）。
- Phase 0.5-C 的硬化项（重启恢复、幂等并发、审计、API v1 冻结）——0.5-A 遗留的 D4/D6/D7 也不在本期重开。
- Pi **SDK in-process** 路线（`createAgentSession`）不实现，只保留接口位（见 D2）。
- 读语义 v2（未读/游标）与事件唤醒机制不改。
- 快任务通道（`delegate_*`）属 Phase 2，不做。

## 6. 契约层（B01）

### 6.1 六个语义方法

门禁文档要求「see / inject / interrupt / attach / resume / caps 六个方法；新增 Agent 不改核心」。落成 TS 契约：

~~~ts
export type AdapterCapability = "see" | "inject" | "interrupt" | "attach" | "resume";

export interface AgentDriver {
  readonly agent: AgentName;
  /** 本 Agent 的能力声明（PRD FR-0.6：没声明就不暴露） */
  readonly caps: SessionCaps;

  /** 发现：扫原生会话（Codex=rollout 文件，Pi=session 文件，Claude=既有实现） */
  discover(opts: { cwd?: string; limit?: number }): Promise<SessionRef[]>;

  /** 建立/重连控制通道（Codex/Pi=ACP/RPC 会话；不抢占 driver 权） */
  attach(ref: SessionRef): Promise<void>;

  /** 读：可选。Pi 在管会话可走 RPC get_messages，Codex/Claude 走文件；
   *  未实现时由路由层回落到统一的文件 transcript 读取（readTranscript） */
  see?(ref: SessionRef, cursor: string, limit?: number): Promise<SeeResult>;

  inject(ref: SessionRef, text: string): Promise<{ messageId: string; effective: "now" | "next_turn" }>;
  interrupt(ref: SessionRef): Promise<{ stopReason: string }>;
  resume(ref: SessionRef): Promise<void>;

  /** 原生终端接管出口：返回命令数组与模式 */
  handoff(ref: SessionRef): Promise<{ command: string[]; mode: "resume-tui" | "attach" }>;

  onUpdate(cb: (update: AdapterUpdate) => void): () => void;
  dispose(): Promise<void>;
}
~~~

语义边界：`attach` = 首次建立控制通道（无既有 adapter 会话）；`resume` = 接管已存在会话（handoff 回来后 / daemon 重启后）。两者底层调用可能相同，但**入参与幂等要求不同**，实现里不得合并成一个无参函数。

- `AgentAdapter`（现有 ACP 子进程接口，`adapters/types.ts`）保留为**内部实现细节**：`ClaudeDriver` / `CodexDriver` 内部组合它，不把 ACP 细节漏到路由层。
- `caps` 是**唯一**能力裁决源：`AgentRouter.assertCap(agent, cap)` 读它，缺失即 `E_CAP_UNSUPPORTED`（422）。

### 6.2 路由

~~~ts
export interface AgentRouter {
  get(agent: AgentName): AgentDriver | null;          // 未注册 → null
  list(): AgentStatus[];                               // GET /agents 的数据源
  assertCap(agent: AgentName, cap: AdapterCapability): AgentDriver; // 不满足 → E_CAP_UNSUPPORTED
}
~~~

`AgentStatus = { agent, available, version: string | null, caps: SessionCaps, reason?: string }`：
`available=false` 时 `reason` 必须是机器可读码（如 `E_AGENT_UNAVAILABLE: codex 未登录`），UI 直接显示，不猜。

0.5-B 新增的两个 HTTP 入口（B08）：

- `GET /api/cp/sessions/discover?agent=<agent>&cwd=<path>&limit=<n>` → `{ sessions: SessionRef[]; count: number }`。`agent` 必填；未注册/不可用 → 422 `E_AGENT_UNAVAILABLE`；`limit` 缺省 100、必须是正整数。发现结果只做「缺失时插入 / 补缺失的 transcriptPath」，不覆盖已有会话的 status/driver。
- `POST /api/cp/sessions`，body `{ agent, nativeId, cwd, key?, transcriptPath? }` → `{ session: SessionRef; created: boolean }`。重复 key 返回 `created:false`，保留已有 status/driver/caps/transcriptPath；未注册/不可用 agent → 422 `E_AGENT_UNAVAILABLE`。

### 6.3 错误码增量

沿用 0.5-A 的九个码，新增一个：

| 码 | 状态 | 语义 |
|---|---|---|
| `E_AGENT_UNAVAILABLE` | 422 | Agent 未安装 / 未登录 / adapter 起不来；**不注册工具、不显示按钮** |

其余（`E_SESSION_NOT_FOUND` / `E_LEASE_CONFLICT` / `E_NO_LEASE` / `E_CAP_UNSUPPORTED` / `E_ADAPTER_DOWN` / `E_RESUME_REJECTED` / `E_IDEMPOTENCY_CONFLICT` / `E_BAD_REQUEST` / `E_UNAUTHORIZED`）语义不变；Gate 要求的四类失败路径全部映射到既有/new 码，不新增自由文本。

## 7. 发现层（B02 + Pi 侧）

### 7.1 Codex：原生 rollout 文件是唯一主源

- 路径：`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`（实测本机已有 2026/10/22、2026/11/10 等目录）。
- 首行 `session_meta.payload` 已含全部发现所需字段：`session_id`/`id`（thread id）、`cwd`、`timestamp`、`thread_source`、`cli_version`、`originator`、`runtime_workspace_roots`。
- 过滤规则：
  1. `cwd` 精确匹配（路径规范化 + Windows 盘符大小写不敏感），与 Claude 的 cwd 发现边界一致；
  2. 默认只列 `thread_source = "user"`（子代理/系统线程不进展台）；
  3. `~/.codex/archived_sessions` 默认**不进列表**（保留开关）。
- 索引：内存 `Map<threadId, {path, mtimeMs}>`，启动时只读首行扫最近 **30 天**，之后按目录 mtime 变化增量补；**不落库**（schema 保持 v3）。
- 性能预算：1000 个 rollout 首扫 ≤ 1.5s（只读首行，不解析全文）。
- **禁止**把 ACP `session/list` 当发现主源（A7 实测：原生 thread 不在 ACP 列表里）。
- ACP 新建的 Codex 会话在 dispatch 时拿不到 rollout 路径（文件由 codex 自己落盘）：dispatch 返回的 `transcriptPath` 允许为空，发现层按 thread id 命中后**补写**（lazy resolve）；期间 `see` 返回空消息 + `pending:true`，不报错。

### 7.2 Pi：靠文件首行，不靠目录名

- 路径：`~/.pi/agent/sessions/<dir>/*.jsonl`，文件名形如 `<ISO ts>_<uuid>.jsonl`。
- **不推断目录名**：实测 `--E--pi-workbench--`、`--C--Users-huang--` 的 mangle 规则与 Claude 不同，因此一律读首行
  `{"type":"session","version":3,"id":...,"timestamp":...,"cwd":...}` 取 `cwd` / `id` 作为权威来源。
- `version !== 3` → 标记 `unsupported`，跳过并计数（不猜格式）。

## 8. Codex 适配器（B03）

- 依赖：新增 `@agentclientprotocol/codex-acp@2.6.0`（npm `latest` 即 2.6.0，与本机 spike 实测版本一致）；`config.yaml` 增 `codex.adapterCmd`，缺省走包入口 `[node, <bin>]`。
- 控制路径：ACP `initialize` → `session/resume(threadId)` → `prompt` / `cancel`（A6/A8 已验证）。
- **运行中 resume 的保守处理**：Codex 运行中 ACP resume 的行为未验证（技术验证 §5 明确列为未验证项）。实现按 Claude 的 quiesce 语义先 `cancel`，等 `idle` 超时 **15s** → `E_RESUME_REJECTED`，不静默重试。
- 兜底：ACP adapter 起不来（未安装/崩溃）→ 一次性的 `codex exec resume <threadId> --json`（短任务语义，发 `notice` 标记降级）；**长会话驱动不放弃 lease**。
- handoff 出口：`["codex","resume",threadId,"--no-alt-screen"]`，子进程需 `TERM=xterm-256color`（A10 实测）。
- caps 初值：`stream/inject/interrupt/resume/transcript = true`；`attach = false`（Codex 无 attach 语义）；`permissions = false`（未观测到 ACP permission 请求，实测到才置 true）；`background = false`。

## 9. Pi 适配器（B04）

- 依赖：`@earendil-works/pi-coding-agent@1.5.2`（本机全局已装）作为 **devDependency（类型）** + **运行时动态 `import()`**；解析不到 → `E_AGENT_UNAVAILABLE`（Pi 包体积大，不做 npx 回落）。
- 通道：包导出的 `RpcClient` 起 `pi --mode rpc`（stdio JSONL；`RpcClient` 已做命令/响应关联与事件分发，不自己拼协议）。
- 命令映射：

| 契约方法 | RPC 命令 | 备注 |
|---|---|---|
| attach / resume | `--session <abs file>` 启动，或 `switch_session` | 打开既有会话 |
| inject | `prompt` | 运行中可 `steer` / `follow_up`（默认 `prompt`） |
| interrupt | `abort` | 返回 stopReason 归一化 |
| see | `get_messages` / `get_entries`（在管会话）；文件增量（未接管） | 两条路径产出同一 `UnifiedMessage` |
| discover | 文件首行扫描（§7.2） | 不需要 RPC |

- 事件：RPC 事件流（run / message / tool / queue / compaction / retry）→ `AdapterUpdate`；未知事件类型 `debug` 跳过，不抛。
- **lease 强制**：A11 实测两个 `pi --mode rpc` 进程可同时打开同一 session 文件且无锁。因此：
  1. 所有 Pi 写操作（inject/interrupt/handoff）必须先持 lease（与 Claude 同一套 `LeaseManager`）；
  2. adapter 层再断言「当前持有者 clientId 与请求一致」，双保险；
  3. Gate 用例：第二客户端 inject → **409 `E_LEASE_CONFLICT`**。
- handoff 出口：`["pi","--session",<abs session file>]`（A12 实测可看到历史）。
- caps 初值：`stream/inject/interrupt/resume/transcript = true`；`attach = false`（「打开同一会话文件」≠ 接管运行中会话）；`permissions = false`（Pi 无 ACP 权限握手）；`background = false`。
- **D6 预检**：B04 第一个 Step 跑最小 `prompt`（无工具、短输出）；402/鉴权失败 → 记录到 `docs/evidence/phase-0.5b/pi-provider.md` 并降级（see/dispatch-only），Gate 里如实标注。

## 10. 统一 transcript（B05）

> 2026-11-16 实测补充（见 `docs/evidence/phase-0.5b/probe-findings.md`）：RpcClient 的 `cliPath` 默认是相对路径，必须传包内 `dist/cli.js` 绝对路径；`newSession()` 只返回 `{cancelled}`，新会话 id/文件路径要从 `getState()` 的 `sessionId`/`sessionFile` 取。

### 10.1 类型上移

`UnifiedMessage` / `UnifiedRole` / `UnifiedKind` 移到 `@pi-workbench/shared`；`transcript/claude.ts` 改为导入。**不改变**任何字段语义（id / role / kind / text / ts / toolName?），避免动 0.5-A 的断言。

### 10.2 三个解析器

统一入口 `readTranscript({ agent, path, cursor, limit })`，内部按 agent 分派；游标仍是**文件字节偏移字符串**（`read_cursors` 表结构不变）。

### 10.4 健壮性

- 未知 `type` / `payload.type`：跳过 + 计数，**不抛**（Gate：未知事件不导致 daemon 崩溃）。
- 坏行（JSON 解析失败）：跳过 + 计数，继续读到 EOF。
- 文件变短（被重写/轮转）：游标归零 + 发 `notice` 事件，不静默返回空。
- 证据要求：B05 先产出记录枚举证据（每类记录计数 + 映射裁定），解析器以它为准写测试 fixture。实际按 Agent 拆成 `docs/evidence/phase-0.5b/codex-records.md`（23 种 type|payload.type）与 `pi-records.md`（21 文件 / 404 记录）。

## 11. 路由与能力门禁（B06）

- `GET /agents` → `AgentStatus[]`（`available/version/caps/reason`），全部来自注册表。
- `POST /dispatch` 接受 `agent`（缺省 `claude`，保持 0.5-A 调用方兼容）；未注册 → 422 `E_AGENT_UNAVAILABLE`。
- 能力门禁：`inject`/`interrupt`/`handoff` 前一律 `assertCap`；不满足 → 422 `E_CAP_UNSUPPORTED`，**不产生任何 adapter 调用**。
- Pi 扩展：`cp_dispatch` 增加可选 `agent`；本地先按 `/agents` 的 caps 预检，缺能力直接返回结构化错误（不空跑一次网络请求）。
- 事件侧：`pipeline` 现有「未知 kind 丢弃 + 日志」逻辑已满足 Gate，补 codex/pi 的坏记录用例即可。

### 11.1 可用性探测（`/agents.available`）

启动时探测一次、`GET /agents` 前可缓存 30s：

| Agent | 探测方式 | 超时 | 失败判定 |
|---|---|---|---|
| claude | 解析 `claude-agent-acp` 包入口 | — | 解析不到 → false |
| codex | `codex --version` + `~/.codex/auth.json` 存在 | 3s | 非零退出/超时 → false |
| pi | 动态 import pi 包 + `pi --version` | 3s | 任何一个失败 → false |

## 13. Handoff / Handback 分流

| Agent | handoff 出口 | 前置 | handback |
|---|---|---|---|
| Claude 交互式 | `claude --resume <id>` | cancel → idle → checkpoint → close | `session/resume` + transcript 增量（0.5-A 已验） |
| Claude 后台 | `claude attach <id>` | 同上 | 同上（先 `claude stop`） |
| Codex | `codex resume <id> --no-alt-screen`（`TERM=xterm-256color`） | cancel → idle → checkpoint | ACP `session/resume(threadId)` + rollout 增量 → deltaSummary |
| Pi | `pi --session <abs file>` | release lease → checkpoint | 重新 `--session` 打开 + `get_messages` 增量 → deltaSummary |

三种 Agent 共用同一个 `TakeoverEngine` 流程骨架：`assertLease → quiesce → checkpoint → handoff(ref) → lease=human`；handback 对称。差异只在 `driver.handoff()` 与 resume 实现。
