## 1. 评估边界

### 1.1 目标约束（来自 PRD）

- **Pi 是唯一入口，且是唯一控制面**：会话调度、状态查看、接管都从 Pi 发起
- **个人轻量**：一个人能维护、能看懂、能改
- **中文优先**：记忆与知识库主要服务中文内容
- **Windows 原生可用**：Windows 11 + Git Bash，不要求 WSL
- **100–500 篇知识库**：中型个人库，不追求企业级 RAG
- **可迁移**：记忆/知识以 Markdown / SQLite 落盘，不被 SaaS 锁死

### 1.2 明确不做（YAGNI）

- 不重写 Agent loop、会话存储、流式协议、Provider 抽象、MCP Client
- 不引入向量数据库 / Embedding 服务 / Reranker（v1）
- 不做跨 Agent 记忆实时同步（PRD 决策 2）
- 不做公网暴露；远程只走 Tailscale + token
- 不承诺第三方插件**运行时**可移植（Claude 插件市场、DSH 一万多插件）

## 2. 市场扫描：有没有成熟方案

### 2.1 大平台 / 通用 Agent 平台

| 项目 | 规模/状态（截至 2026-11-13） | 能提供什么 | 为什么不是答案 |
|---|---|---|---|
| **Open WebUI** | 约 158k stars；v0.13.0（2026-11-04） | Chat UI、RAG、Tools、MCP、sub-agents | 它自己就是 Agent Runtime；Pi 只能作为 OpenAI 兼容模型接进去，违反"Pi 唯一控制面"；Pipelines 已 deprecated |
| **LibreChat** | 约 47k stars；MIT | Agents、MCP、Skills、多模型 Chat | 同上：平台成为 Runtime；记忆/知识库在它自己的库里 |
| **LobeHub** | 约 85k stars | Super-Agents、插件、模型市场 | 平台型产品，重；不适合个人轻量 |
| **Goose** | 约 56k stars；Rust | 桌面 + CLI + API，MCP 70+，ACP providers | 最接近的成熟替代品，但有自己的 Runtime；用它等于放弃 Pi 的会话/记忆 |
| **Khoj** | 约 38k stars | 个人第二大脑，Web/桌面/手机/WhatsApp | 产品形态最接近，但 Python 栈、自己的 runtime |
| **AnythingLLM** | 成熟 | 桌面/自托管 RAG 工作区 | 独立 RAG 产品，不是 Pi 的薄扩展 |
| **Dify / n8n** | 成熟 | 工作流 / 自动化平台 | 工作流编排，不是个人记忆型 Agent |
| **LangGraph / CrewAI / AutoGen** | 成熟 | Agent 编排框架 | 会替代 Pi 的 loop；Python 为主；对个人场景过重 |

**结论**：它们的共同问题是**架构反转**——自己当 Agent Runtime，Pi 只能当模型或工具。可借鉴 UI / 工具卡片 / RAG 思路，不适合作主骨架。

### 2.2 个人 Agent 工作台（更接近的品类）

| 项目 | 状态 | 可借鉴 | 结论 |
|---|---|---|---|
| **Auro_agent** | 31 stars，早期，Python/LangGraph | 本地优先、memory/skills/partners/workflows 的产品结构 | 只作参考 |
| **Sorana** | 5 stars，极早期 | "Personal AI Knowledge Workspace" 的交互 | 太早期 |
| **Khoj** | 38k stars，成熟 | 第二大脑、知识库、移动端 | Plan B，会替换 Pi |
| **Goose** | 56k stars，成熟 | 桌面 + CLI + MCP + ACP | Plan B，会替换 Pi |

**结论**：品类本身仍在早期；没有一个成熟方案同时满足「Pi 唯一控制面 + 个人记忆 + 中文知识库 + 轻量可改」。

### 2.3 其他类别

- **Coding Agent / IDE 插件**（OpenHands、Cline、Roo Code、Aider）：强在代码任务，但会替代 Pi 的入口，且没有个人记忆/知识治理。
- **Memory 框架**（Letta、Mem0、Zep）：能解决"记忆"单点，但通常引入服务/数据库/额外模型调用；Pi 记忆是唯一 source of truth，外挂服务会造第二套真相。
- **RAG 平台**（RAGFlow、AnythingLLM）：企业文档问答导向，对 100–500 篇个人库过重。

### 2.4 协议与最佳实践

| 协议 / 原则 | 定位 | 对我们的用法 |
|---|---|---|
| **MCP** | 模型 ↔ 工具/数据 | **接管"工具"的唯一通用层**；Pi 内置 Client（stdio + streamable HTTP + OAuth + tool exposure） |
| **ACP**（Zed） | 客户端 ↔ Agent：`session/new`、**`session/load`**、`session/prompt`、`session/cancel`、`session/set_mode`、`session/request_permission`、`fs/*`、`terminal/*`、`elicitation/*` | "接管"语义最标准的协议；v1 只借概念，未来作标准化出口 |
| **A2A** | Agent ↔ Agent：Agent Card 发现、Task 生命周期、contextId、Artifact、SSE、push | 借任务模型；其 *Why Agents Are Not Tools* 是"子代理不够用"的官方依据 |
| **12-Factor Agents** | Factor 5 统一执行/业务状态、Factor 6 launch/pause/resume、Factor 7 用工具联系人类、Factor 11 从任何地方触发 | 接管设计（检查点、交接、单写入者）的方法论依据 |
| **Anthropic《Building effective agents》** | 先可组合模式（routing / orchestrator-workers），别一上来全自主 | Pi 父会话 + 角色化子代理 = orchestrator-workers |

## 3. Pi 生态扫描：哪些轮子能直接用

### 3.1 候选包总表（2026-11-13 实测）

| 包 | 版本 / 发布 | 规模 | 覆盖范围 | 结论 |
|---|---|---|---|---|
| **pi-subagents** | 0.88.1 / 2026-11-13（**几小时前**） | 11.3 MB，MIT，935.8K/月下载，5 依赖 + 5 peer | 子代理编排 | **采用，但仅作快任务通道** |
| **@ygncode/pi-web** | 0.0.1-beta.38 / 2026-09-27 | 14.3 MB，MIT，运行时依赖仅 `qrcode`，**有 postinstall** | Web/PWA/远程 | **A/B 候选**（7 周未更新 + beta） |
| **@gang-of-beads/pi-web** | 2.202611.0 | 16.7 MB，MIT，`engines: node>=22.19`，导出 `plugin-api` / `server-plugin-api`，自带 `sessiond` | Web/PWA/远程 | **A/B 候选**（工程化更完整） |
| **pi-memory** | 0.4.2 / 2026-08-11 | 107 KB，6 文件，MIT，有 postinstall | 记忆 | 不采用；借文件布局与 recovery 思路 |
| **pi-knowledge** | 0.14.0 / 2026-11-12 | 458 KB，**16 依赖**（better-sqlite3、tree-sitter×9、@huggingface/transformers） | 知识库/RAG | 不采用；作中文检索基准 |
| **pi-local-rag** | 0.4.1 | SQLite FTS5 + sqlite-vec + ONNX | 知识库 | 备选；中文未验证 |
| **pi-mcp-adapter** | 7.0.1 | 5 MB，MIT，1.8M/月 | MCP 增强 | 可选；Pi 内置 MCP 已够 |
| **pi-acp** | 0.0.34 | MIT | Pi 作为 ACP agent | 未来接编辑器时用 |

### 3.2 pi-subagents：事实

- 内置角色：`scout`、`researcher`、`evidence-auditor`、`worker`、`reviewer`、`oracle`、`delegate`
- 前台子会话（在同一进程内流式展示）+ 后台子会话（detached runner）
- FleetView / `/subagents-fleet` 观测、`maxSubagentSpawnsPerRun` 递归 guard、`/subagents-doctor`
- 要求 Pi ≥ 1.2.0；`toolActivation` 可控制 `subagent` 工具是否常驻
- 官方文档索引列有 **external CLI runners** 一节（⚠️ 具体 profile 名与权限档位未验证，Phase 0 实测）

**在 v0.3.0 中的位置**：**快任务通道**。它解决"调用"，不解决"接管"——派发即一次性进程，无会话可接管。

### 3.3 pi-web 两案：事实（选型待 Phase 0 裁决）

**@ygncode/pi-web**
- 描述：Remote control your pi coding agent from any browser on your network
- 运行时依赖只有 `qrcode`；peer 依赖 `pi-tui` / `pi-coding-agent` 为 `*`
- 有 `postinstall` / `preuninstall` 生命周期脚本（会写自启等）→ **安装前需审脚本**
- 多会话、树视图/fork、schedules、notes、`PI_WEB_TOKEN` 鉴权、Tailscale Serve + `/remote` 二维码
- 风险：beta；最后发布 2026-09-27（约 7 周）

**@gang-of-beads/pi-web**
- 16.7 MB，`engines: node>=22.19`，导出 `./plugin-api`、`./server-plugin-api`
- 二进制：`pi-web`、`pi-web-server`、`pi-web-sessiond`（独立 sessiond 守护）
- 插件页更全（Files/Git/Terminal/Goals）；历史上仅支持 Linux/macOS/WSL → **Windows 需实测**

**共同缺口**：两者都是**聊天式 UI**。v0.3.0 的控制台需要**会话矩阵 + 接管视图 + 租约状态**，属于结构性差异，不是加一页能补的。

### 3.4 pi-memory：为什么不能直接套

**能做**：`~/.pi/agent/memory/` 下 `MEMORY.md` + `daily/` + `SCRATCHPAD.md` + recovery；工具 `memory_write/forget/restore/read/scratchpad/status/search`（search 依赖 qmd）；每轮注入 scratchpad + 今日 daily + MEMORY.md（上限 16K）；有 KV cache-stable snapshot 设计。

**不匹配**：schema 是自由文本日志，不是 PRD 的 `name/description/metadata.type/updated/confidence` frontmatter；没有 `memory_list`；冲突模型是追加/恢复而非"新者胜"；注入策略是每轮注入 daily 而非 session_start 注入 profile；中文搜索未验证；2026-08-11 后未更新。

**结论**：借它的文件布局、recovery、snapshot 思路，按 PRD schema 自研约 500–700 行。

### 3.5 pi-knowledge / pi-local-rag：为什么过重

- **pi-knowledge**：BM25 + 向量 + rerank，code/doc/PDF/URL 索引。但 16 依赖、`better-sqlite3` + `tree-sitter` 原生模块、`@huggingface/transformers` 推理，面向代码库/多 KB；工具名与存储都不是 PRD 的 `kb_*`。对 100–500 篇中文个人文档属"能力过剩 + 依赖过重"。
- **pi-local-rag**：SQLite FTS5 + sqlite-vec + ONNX，PDF/DOCX/HTML/OCR，per-project，auto-injection。中文效果未验证；per-project 模型与全局知识库不一致。

**结论**：作为中文检索基准/备选，不直接采用。

## 4. 关键事实与本机实测

### 4.1 DSH 不是 MCP Server

**事实**：DSH 0.2.2-rc 是 Electron 桌面应用；`~/.dsh/dsh-windows-mcp/toolchain/0.8.8/windows-mcp/` 是 Python venv，含 `windows_mcp/__main__.py` 与 `fastmcp` —— 它是 **MCP Server**，但被 **DSH 作为 Client 消费**。DSH 自身不对外提供 MCP Server，没有独立 CLI；Web GUI `127.0.0.1:11643` 需鉴权、`/v1/models` 404、`/api/*` 401。

**可用路径**（详见 PRD §3.6）：① Pi 直连 `windows-mcp`（`pi mcp add windows -- python -m windows_mcp`）；② DSH 侧实现 MCP Server 插件；③ pty/tmux 兜底。

### 4.2 Pi 没有内置 Web Server / UI

Pi 1.5.2 有 SDK、RPC、会话 JSONL、扩展、MCP，**没有**内置 Web server。控制台这一层必须来自"改造现成产物"或"自研"。

### 4.3 中文检索：MiniSearch 不是唯一解（本机实测）

用 Node 24 的 `node:sqlite` 内存库，500 篇中文文档（每篇约 2–3 KB）：

| 场景 | 结果 |
|---|---|
| 3 字以上查询（如「中文检索」「记忆系统」「个人知识库」） | FTS5 trigram + BM25 列权重：**0.3–0.6 ms** |
| 2 字查询（如「记忆」「桌面」「数据」） | trigram 分词器要求 ≥3 字符，**MATCH 返回空**；`LIKE '%记忆%'` 回退：500 篇 **0.09 ms**，结果正确 |

**结论**：**FTS5 trigram + 2 字 LIKE 回退**对 100–500 篇足够快、足够准；比 MiniSearch 少一套索引/分词代码，且天然持久化、增量更新。语义检索留到以后（`sqlite-vec` 或 pi-knowledge），不影响 schema。

⚠️ 上述为**合成语料**基准，Phase 0 需用真实 100–300 篇文档复测 recall@5。

### 4.4 Tauri 不是 MVP 必需

pi-web 是 PWA，Windows/macOS/Linux 浏览器可安装，手机可加到主屏；自带 Windows Run-key 自启。Tauri 主要多一个原生窗口/安装包，不增加核心能力 → v1 用 PWA。

### 4.5 CLI 可用性

| CLI | 状态 |
|---|---|
| `claude` | 已安装，`--version` = **2.1.323** |
| `pi` | 已安装 **1.5.2**（文档齐全，`~/.pi/agent/` 干净，无 packages 声明） |
| `codex` | shim 存在（`AppData/Roaming/npm/codex.cmd`），**版本与登录状态未验证** |
| DSH | 0.2.2-rc，无 CLI |

⚠️ pi-subagents 的外部 adapter 只校验二进制存在，**不验证登录**，Phase 0 必须做真实 smoke。

## 5. 路线对比

### 5.1 五条路线

| 路线 | 做法 |
|---|---|
| **A 全定制** | pnpm monorepo；自写 Pi 扩展 + 服务端 + React 前端 + 检索 + Tauri |
| **B 全拼装** | pi-subagents + pi-web + pi-memory + pi-knowledge，全部现成 |
| **C 混合**（选定方向） | Pi + pi-subagents（快任务）+ 控制台（改造 pi-web 或自研）+ **自研记忆/知识/控制面** |
| **D DSH 核心** | 用 DSH 的 GUI/IM/cron/skills，Pi 作模型或工具 |
| **E 平台前端** | 把 Pi 包成 OpenAI 兼容 API，接 Open WebUI / LibreChat |

### 5.2 成本对比（工期口径与 PRD §七 一致）

> **控制面（约 7–10.5 天）是 v0.3.0 新增的共同增量**，所有路线都要付，故单列。

| 路线 | 骨架自研 LOC | 记忆/知识自研 LOC | 控制面 | 工期 | 架构契合 | 结论 |
|---|---|---:|---|---:|---|---|
| A 全定制 | 6–8k | 含在内 | 1.2–1.8k | 22–27 天 | 高 | 不选 |
| B 全拼装 | 0–0.5k | 0（schema 不匹配） | 1.2–1.8k | 9–14 天 | 中 | 不可作最终 |
| **C 混合** | 0.2–0.3k | 1–1.4k | 1.2–1.8k | **15–20 天** | **高** | **选定** |
| D DSH 核心 | 0–0.5k | 0 | 受 DSH 限制 | 9–14 天 | 低 | Plan B |
| E 平台前端 | 0.5–1k | 0 | 0.6k（适配层） | 12–17 天 | 低 | 不选 |

**路线 C 的取舍**：复用最难的部分（Agent loop、子代理进程管理），自研最有价值的部分（记忆 schema、中文检索、接管协议）；代价是 pi-web beta 风险 + 控制面自维。
