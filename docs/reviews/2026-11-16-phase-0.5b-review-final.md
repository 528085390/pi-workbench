## 4. P0-1 详解（唯一的合并阻断项）

### 4.1 现象

`index.ts:303-317` 给 CodexDriver 注入的写守卫：

```ts
const lease = leases.current(ref.key);
if (lease !== null && lease.clientId !== PI_AGENT_CLIENT_ID) {   // "pi"
  throw new WorkbenchError("E_LEASE_CONFLICT", …);
}
```

调用方的真实身份是 `pi:<pid>`（`extension/src/index.ts:282`），而引擎只在 `agent === "pi"` 时做租约换名（`takeover.ts:542`）。所以 codex 会话上：

- `POST /inject` → `assertWriter` 通过 → `driver.inject` → 守卫 409；
- `POST /interrupt` → 同样 409；
- handback → 租约是 `handoff-<id>` → `driver.resume` 被拦 → 被 `takeover.handback` 的 catch 包成 **`E_RESUME_REJECTED`**（错误码还错位）。

### 4.2 实测复现（临时脚本，复刻 `index.ts` 注入 + takeover 调用顺序，已删除）

```text
RESULT inject: THROW E_LEASE_CONFLICT — 租约被其他客户端持有：pi:4242
RESULT resume(handback): THROW E_LEASE_CONFLICT — 租约被其他客户端持有：handoff-pi:4242
adapter calls: []          ← 连 adapter 都没起来，没有任何 ACP 请求
```

### 4.3 为什么 341 个测试全绿

| 入口 × 操作 | claude | codex | pi |
|---|---|---|---|
| HTTP `inject`（客户端持租约） | ✅ `api.test.ts` | ❌ **空** | ✅ `api-agents.test.ts` |
| HTTP `interrupt` | ✅ `api.test.ts` | ❌ **空** | ❌ **空** |
| HTTP `handback` | ✅ `api.test.ts` | ❌ **空** | ❌ **空** |
| HTTP `handoff` | ✅ | ✅（`api-agents` 守卫豁免） | ✅ |
| `dispatch` | ✅ | ✅ | ✅（本轮新增） |
| driver 级 inject/interrupt/resume | ✅ | ✅ | ✅ |
| E2E | 全链路 | **仅 driver 级**写 + HTTP dispatch/see/handoff | driver 级 + HTTP dispatch |

codex 的写路径在 API 层是整块空白，E2E 恰好走了 driver 级 —— 这就是 P0 的藏身处。

### 4.4 最小修法（三选一）

- **A（推荐）**：`takeover.#driverWrite` 对所有 driver 做租约换名（去掉 `driver.agent !== "pi"` 早退）。守卫读到的就是引擎身份，语义自洽，改动 1 行。
- **B**：撤掉 driver 级身份守卫，只保留 `TakeoverEngine.assertWriter`（0.5-A 的唯一真相），把 S6 记为「不采纳」并写明理由（driver 看不到调用方身份）。
- **C**：把 acting clientId 穿进 driver 写方法，守卫检查 `lease.clientId === actingClientId`。

必补用例（任选修法都要）：`codex + pi:<pid> 持租约 → inject 200`、`→ interrupt 200`、`handoff 后 handback 200`。顺手把 §4.3 的空格补齐成矩阵，并给 `pi` 补 interrupt/handback 两条。

## 7. 值得记住的两条过程教训

1. **覆盖矩阵比测试数量重要**。341 个绿测试没能挡住一个「agent × 操作 × 入口」级别的空洞。建议把 §4.3 的矩阵直接做成表驱动的参数化测试（3 agent × {inject, interrupt, resume, handoff, attach} × {API, driver}），一次补齐后这类 bug 结构性地不会再出现。
2. **「我修了」要能对应到可复核的产物**。本轮有一处自述（阶段门禁勾选）与实际不符，一处性能基准无可复现脚本。建议修复记录里每条都带 `文件:行` 或命令，像 E2E 证据那样可点开就验。
