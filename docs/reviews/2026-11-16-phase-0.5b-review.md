## 1. 必修（合并前）

### M1. Pi handoff 不断开 RPC 子进程 → 人类接管时同一 session 文件有两个写者

`src/takeover.ts:566-580` 的 `#closeDriverRef`：driver 没有 `close` 就 `return`，注释写「Pi 保持原生会话不动」；`src/agents/pi-driver.ts` 全文确实没有 `close`（只有私有的 `#dropClient`，仅在 RPC 报错或 `dispose` 时调用）。而 handoff 紧接着返回 `["pi","--session",<abs file>]`（`pi-driver.ts:210-213`）。

- 影响：A11 实测「Pi 无文件锁」正是 Gate #3 用 lease 要防的东西。交接后 daemon 的 `pi --mode rpc` 仍在运行，人类终端与它同时写同一个 jsonl。
- 证据里的顺序就是这个：`e2e-three-agents.jsonl` L50 `rpc-attach` → L54 `handoff-pi-driver`，中间没有任何 stop。
- 建议：给 `PiDriver` 加 `close(ref)`（= `#dropClient(ref.key)`），`#closeDriverRef` 才会真正 quiesce；Gate #3 补一条「handoff 后 RPC 子进程数 = 0」。

### M2. codex/pi 的事件流从未进 pipeline，但 `/agents` 报 `stream:true`

`src/server.ts:568-572` 只对 `ref.agent === "claude"` 调 `pipeline.attach(deps.adapter, ...)`；`src/pipeline.ts:93` 的 `attach` 只接受 `AgentAdapter`。grep 全仓：`CodexDriver.onUpdate` / `PiDriver.onUpdate` 除测试外无订阅者。

- 影响：WS 消费者永远看不到 codex/pi 的 token / tool 事件，只有 takeover 自己写的 `notice` / `state_update`。E2E 的 `claude/events` 一行（types 只有 notice/state_update/thought/token，count 12）就是全部事件面的实测结果。
- `test/api-agents.test.ts` 有一条「codex dispatch 成功时不走 Claude 的 pipeline.attach」，说明这是已知选择而非疏忽——那就与 D5「宁可不给按钮」冲突：`caps.stream=true` 实际对外无流可订。
- 建议：`pipeline.attach` 改为接受 `AgentDriver`（内部 `driver.onUpdate`），dispatch 后按 agent 分支 attach；否则把 codex/pi 的 `stream` 降为 `false`，并把 Gate #6 拆成「transcript 统一渲染 ✅ / 事件流未接 ⚠️」。

### M3. `agent=pi` 的 dispatch 走不通，但本地预检放行

`PiDriver` 没有 `newSession`；`src/takeover.ts:394-399` 对非 claude 强制要求它 → `E_CAP_UNSUPPORTED: Agent pi 不支持新建会话`。而 `/agents` 报 pi `inject:true`，扩展 `cp_dispatch` 只查 `caps.inject`（`packages/extension/src/index.ts:514-531`）→ 本地预检通过、远端 422。

- 这正是 D5 要避免的「点了没反应」，也是 spec §1 第 1 条「派发任务给 claude / codex / pi 任一 Agent」未满足的部分。
- 建议：二选一——补 pi 的新建会话路径（spec §18 未决项 #7 已列），或让能力模型能表达「可新建会话」并让 `/agents` / 扩展预检如实拒绝。

### M4. 发现层没有产品出口，E2E 直接写库绕过 API

`AgentDriver.discover` 在生产代码里零调用点（grep 只命中 test）；`server.ts` 没有 discover / register 路由（只有 `/agents`、`/sessions*`、`/dispatch`、`/ws`）。`scripts/e2e-three-agents.mjs:288-299` 的 `seedDaemonDb` 直接 `openDb(workbench.db)` + `registry.upsert(ref)` 注册 codex/pi 会话。

- 影响：真实用户无法让 daemon 认识一个既有的 codex/pi 会话；Gate #2/#3 的「discover 15 条 / 7 条」证明的是库函数，不是产品路径。脚本头部已承认「daemon 没有 discover/resume 路由，0.5-B 非目标」，但 spec §1.1 / §7 的措辞是「同一个 daemon 能发现三者」，二者需要对齐。
- 建议：加一条薄路由（`GET /sessions/discover?agent=&cwd=&limit=` 或 `POST /sessions` 注册发现结果），E2E 改走 HTTP；或者把 Gate #2/#3 标 Conditional，并在 `phase-0.5b-gate.md` 明写「发现经脚本 + 直接落库验证」。

## 3. 清理项

- **三个解析器重复约 350 行**：`transcript/{claude,codex,pi}.ts` 的游标推进、半行处理、`readBytes` / `parseCursor` / `normalizeLimit` 几乎逐字相同，差异只在单行映射（及 codex/pi 的 `skipped`）。抽一个 `scanJsonl(path, cursor, limit, mapper)`，顺带统一 `skipped` 口径。
- **文件变短时静默回退到 0**：`transcript/codex.ts:71`、`transcript/pi.ts:80`。spec §10.4 要求「游标归零 + 发 `notice`，不静默返回空」。
- **discovery 的 `driver` 字段不一致**：pi 发现给 `"pi"`（`discover/pi.ts:99`），codex 给 `"none"`（`discover/codex.ts:124`）。未被接管的原生会话按 `"none"` 更准。
- **常量重复**：`DEFAULT_CODEX_SESSIONS_ROOT` 在 `discover/codex.ts:23` 与 `codex-driver.ts:29` 各定义一份。
- **形状不一致**：`AgentStatus.version: string | null`（`agents/types.ts:20`）vs 扩展 `AgentDescriptor.version?: string`（`extension/src/index.ts:104`）。
- **attach 能力判定有两套**：`takeover.ts:618` 只拦非 claude，claude 走 `ref.kind` / `ref.capabilities`，容易漂移。
- **Pi 发现无深度上限**（`discover/pi.ts:150-170` 递归不设 depth），codex 侧有 `depth > 3`；Pi 侧也没有时间窗，会话多时会变慢。

## 5. 做得好的

- **caps 是真的单裁决源**：`attach=false` 一路落到 422，且在调用 driver 之前拒绝（`server.ts:475-482`）；`/attach` 按会话声明的 caps 而不是 driver 快照，claude 按 kind 分流的细节没被抹平。
- **`#driverWrite` 的临时换租约**（`takeover.ts:534-551`）：在共享 `LeaseManager` 上把 `pi:<pid>` 换成 driver 的 `pi` 身份、`finally` 还原，解决了扩展 clientId 与 driver clientId 不对称的问题，且有对应用例。
- **`PiDriver` 的顺序纪律**：先 `acquire` + `assertWriter` 再拉进程（`#claim` 在 `#ensureClient` 之前），`#call` 失败即 `#dropClient`，所有 RPC 调用带超时——直接对上 A11「无文件锁」的教训和 plan 的全局约束。
- **启动探测的工程细节**：三个探测器并行 + 各自 3s 硬超时 + 失败只降级该行；Windows `.cmd` shim 经 `cmd.exe /d /s /c` 解析，是真踩过 `codex resume --help` 挂住这个坑才写出来的。
- **0.5-A 读路径零冲击**：保留注入式 `TranscriptReader`（`takeover.ts:640`、`server.ts:203`），字节游标语义逐字未动——这是 229 条旧测试没红的关键，也是「回归基线」策略执行到位的地方。
- **任务粒度与可追溯性**：13 个 commit 按 B01-a→B07 一一对应 plan，测试名直接写着 Review Focus 的条目（如「inject 无 lease 时不 spawn adapter、不发 prompt」），评审时几乎不需要猜意图。
