## 0. 执行原则

1. **风险优先。** 先验证会话发现、租约、接管、交回这条最危险的链路，再做 UI、记忆和知识库。
2. **每个阶段必须有可核对的 Gate。** Gate 不是“代码写完了”，而是用命令、事件记录、手工验收或测试证明行为成立。证据写到 docs/evidence/ 或对应阶段的验收记录。
3. **不满足 Gate 不进入下一阶段。** 连续两次 Gate 失败时，先缩小范围或走回退方案，不把问题推到下一阶段。
4. **能力必须真实。** Adapter 声明 SessionCaps；只有实测通过的能力才注册工具、才在 UI 显示按钮。
5. **单 driver 是硬约束。** 任何 inject / interrupt / handoff 都必须先持有租约；没有租约的 adapter 只允许 see。
6. **原生会话只读。** 控制面读取 Claude/Codex/Pi 的 transcript 时只读不改；所有写入走对应 Agent 的控制通道。
7. **本工作区不生成文档备份。** 直接修改正式文件；需要对比或回滚时用 git 历史，不创建 .bak。

## 3. Phase 0.5-A — Pi 与 Claude 垂直切片

### 目标

用最短路径跑通一条真正的“可接管联通”：

Pi -> control-plane -> Claude 会话 -> 事件回传 -> inject/interrupt -> 原生终端接管 -> resume 回 Pi

这一阶段只接 Claude，不接 Codex、Pi 托管会话、DSH，也不做 Web UI。

### 先做风险前置：A00

**A00. 验证 handoff 的会话载体。** ✅ 通过（2026-11-14）

> 结论：**方案 A 成立**。ACP `session/new` 的会话 id 就是 Claude 原生 sessionId，transcript 落在 `~/.claude/projects/<cwd>/<id>.jsonl`；原生 `claude --resume <id>`（TUI 与 `-p`）能接上并保留上下文，ACP `session/resume` 能交回。
> 修正：**`claude attach` 只对 `--bg`（kind=background）会话有效**，对 ACP 会话报 `No job matching`。handoff 出口按 session kind 分流：interactive → `claude --resume`，background → `claude attach`。
> 证据：`docs/evidence/phase-0.5a-a00.md`、`spike/acp-probe/evidence/a00-claude-carrier.jsonl`、`a00b-tui-takeover.jsonl`。

- 方案 A：ACP session/new 创建的会话，能否用 claude --resume / claude attach 在原生终端接上。
- 方案 B：如果方案 A 不行，dispatch 改为先创建 claude --bg 原生会话，ACP 通过 session/resume 控制；接管时先 quiesce，再 claude attach。
- 记录：哪种方式保留上下文、哪种方式能双向交回、失败时的错误原文。

**A00 不通过，不进入 A01-A08 的完整实现。** 先确定载体，避免在错误前提上写 adapter。

## 12. 通用 Gate 审核模板

每个阶段结束时填写：

~~~text
Gate:
Date:
Phase:
Goal:
Evidence:
  - command:
    result:
  - manual:
    result:
Pass / Conditional / Fail:
Known limitations:
Decision:
  - proceed
  - fix and re-run
  - narrow scope
  - fallback
Next owner / next step:
~~~

判定规则：

- **Pass**：所有必选项有证据，且连续 2 次通过。
- **Conditional**：只允许不影响下一阶段核心假设的缺口；必须写明补做时间。
- **Fail**：核心路径不成立，停止进入下一阶段。
