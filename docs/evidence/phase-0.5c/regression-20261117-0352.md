## 三 Agent 回归（C07）

- Claude：dispatch → WS 事件 → transcript（assistant 产出）→ inject 回显 → interrupt → checkpoint → handoff（`claude --resume <id>`）→ 原生 human-turn → handback `resumed=true` + deltaSummary 含人类回合。
- Codex：`codex exec` 造 rollout → discover → 按原生 thread id resume → inject 回显 → handoff `codex resume <id> --no-alt-screen`。
- Pi：真实 `pi --print` 造 session → RPC attach → inject 回显 → 第二写者 `E_LEASE_CONFLICT` 且不新增 RPC 子进程 → handoff `pi --session <file>`。

- 错误形状：`422 E_AGENT_UNAVAILABLE`、`404 E_SESSION_NOT_FOUND`、`409 E_RESUME_REJECTED` 均结构化返回。

## 已知限制（写入文档）

1. **Claude interactive `attach=false`**：重启后 `POST attach` 返回 `422 E_CAP_UNSUPPORTED`，无法演练"attach 200 后 inject"；会话记录与 transcript 不丢已由 `e2e-restart` 证明。契约见 `docs/api/cp-v1.md` §4。
2. **Windows 优雅关闭不可测**：Node 在 Windows 的 `SIGTERM` 即 `TerminateProcess`，daemon 的 SIGTERM handler 不执行，`e2e-faults` 的 `graceful-shutdown-ended-at` 显式 SKIP；需在 POSIX + `PI_WORKBENCH_E2E_SHUTDOWN=1` 补测。
3. **单机单 daemon**：实例锁依赖 `workbench.pid` 的 pid 存活判断，跨用户/容器不保证。
4. `e2e-restart` 自起 daemon 时已注入 `winEnv`（`scripts/e2e-restart.mjs:221`），`/health.adapters` 与 `/agents` 共用同一探测缓存；终审修复轮复跑三个 agent 均 `available=true`。三 Agent 行为可用性仍以 `e2e-three-agents` 为准。
