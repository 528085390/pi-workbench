# Phase 0.5-C 控制面硬化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Pi Workbench 控制面从演示级硬化到可长期运行：重启可恢复、dispatch 幂等、租约与子进程可控、API v1 可冻结。

**Architecture:** 在现有单机单 daemon 结构上做加法：SQLite schema v3→v4（实例表、审计表、归属列），启动时先抢实例锁再迁移、清扫、对账；写操作经 per-session 队列串行化；dispatch 预留记录支持 TTL 回收与 24h 保留；新能力全部挂在既有 Fastify 路由前缀 `/api/cp` 下，并用契约测试锁住路由集合。

**Tech Stack:** Node 24（`node:sqlite`、`node:test`、`--experimental-strip-types`）、TypeScript、Fastify 5、@fastify/websocket、pnpm workspace。

**Spec:** `docs/specs/2026-11-17-phase-0.5c-control-plane-hardening.md`

## Global Constraints

- 单机单 daemon：跨实例只靠 `workbench.pid`，不引入分布式租约或 HA。
- 原生 transcript 只读；控制面绝不改写 Claude / Codex / Pi 的会话文件。
- schema 迁移 expand-only：只加表、加列、加索引，不删列、不改既有列语义；升级前备份库文件，保留最近 2 份。
- 所有新错误码必须同时加进 `WorkbenchErrorCode`（`src/errors.ts:7`）与 `STATUS_BY_CODE`（`src/server.ts:141`）。
- 控制面默认只监听 `127.0.0.1:7331`；不新增公网端口。
- 测试统一用 `node --test --experimental-strip-types "test/<name>.test.ts"`；提交前跑 `pnpm -C packages/control-plane test`。
- 不生成 `.bak` 文档备份；需要回滚用 git。
- 证据文件按 run 命名：`docs/evidence/phase-0.5c/<gate>-<yyyyMMdd-HHmm>.md`。

## Review Focus

- **半迁移的库**：`PRAGMA user_version` 已写 4 但 v4 DDL 只执行了一半（进程在迁移中被杀）时，重启必须能继续迁移而不是报 duplicate column。对应 Task 1 的「重复 migrate 幂等」测试。
- **时钟跳变 / 注入固定时钟**：租约与 dispatch 预留都按 `now` 判定，测试里时间不走会导致死循环或永不过期。对应 Task 3、Task 5 的注入时钟用例。
- **native 进程已死但会话仍 running**：重启对账必须把所有 driver 会话改成 `unknown`，不能保留 running 让上层误判。对应 Task 4 的对账用例。
- **多读者并发写同一会话**：队列按 `sessionKey` 分桶，桶内 FIFO；不同会话必须并行，不能被全局锁拖死。对应 Task 6 的「两个会话并行」用例。
- **WS 回放跨重启**：事件 seq 是 SQLite AUTOINCREMENT，重启后继续递增；客户端用旧 `after` 回放不能丢事件也不能重复。对应 Task 11 的 golden fixture + 回放用例。

- [ ] **Step 3: 实现 DispatchStore 三个方法，并改造 `#resolveReserved`**

- `reclaim`：`UPDATE dispatches SET updated_at = ? WHERE idempotency_key = ? AND status = 'reserved' AND updated_at <= ?`，`changes === 1` 即赢家。
- `touch`：`UPDATE dispatches SET updated_at = ? WHERE idempotency_key = ? AND status = 'reserved'`。
- `pruneRetained`：`DELETE FROM dispatches WHERE status IN ('done','failed') AND updated_at < ?`。
- `dispatch()`：`created === false` 时改成 `const outcome = await this.#resolveReserved(...)`；返回 `{ kind: "retry" }` 表示本调用赢下回收，继续走 `newSession`（把原来的「赢家路径」抽成私有方法 `#createSession(...)` 复用）。
- `#resolveReserved`：reserved 分支里先用 `this.#dispatches.reclaim(idempotencyKey, this.#dispatchTtlMs, new Date(this.#now()))`（构造器从 `deps.dispatchReservedTtlMs ?? DEFAULT_DISPATCH_RESERVED_TTL_MS` 取值）；赢 → 返回 `{ kind: "retry" }`；输 → 继续轮询；轮询耗尽 → `E_DISPATCH_IN_PROGRESS`（替换 `E_ADAPTER_DOWN`）。
