# Phase 0.5-B 三 Agent 统一控制面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让同一个 control-plane daemon 能发现、派发、观察、接管 claude / codex / pi 三种会话，按各 Agent 的 `SessionCaps` 暴露能力，并保持 Claude 的 0.5-A 行为零回归。

**Architecture:** 在现有 daemon 上引入 `AgentDriver` 契约与 `AgentRouter` 注册表，把 `takeover.ts` / `server.ts` 里的 Claude 硬编码抽掉；发现层直接扫原生会话文件（Codex rollout / Pi session），控制层用 ACP（Claude、Codex）与 RPC 子进程（Pi）；transcript 三解析器共用一份 `UnifiedMessage`；写操作一律先过 `LeaseManager`。

**Tech Stack:** Node 24（`node:sqlite`、`node:test`、type stripping）、TypeScript strict、Fastify 5、@agentclientprotocol/sdk 2.6.0、@agentclientprotocol/claude-agent-acp 0.107.0、@agentclientprotocol/codex-acp 2.6.0、@earendil-works/pi-coding-agent 1.5.2（仅类型 + 动态 import）。

**Spec:** `docs/specs/2026-11-16-phase-0.5b-codex-pi.md`

## Global Constraints

- Node ≥ 24，pnpm 12.3.4 workspace；TypeScript strict；不允许 `any`（必要时 `unknown` + 窄化）。
- 监听 `127.0.0.1:7331`；数据目录默认 `~/.pi-workbench`（`PI_WORKBENCH_HOME` 可覆盖）；schema **保持 v3，不新增表**。
- 单 driver 硬约束：`inject` / `interrupt` / `checkpoint` / `handoff` 必须先持 lease，否则 `E_NO_LEASE`；冲突 `E_LEASE_CONFLICT`。
- 原生 transcript 一律**只读**：`~/.claude/projects`、`~/.codex/sessions`、`~/.pi/agent/sessions` 不得写入。
- **所有子进程探测/调用必须带超时**（探测 3s、cancel 等待 15s）：0.5-B 实测 `codex resume --help` 会挂住，裸等待会拖死 daemon。
- 能力不明确 → 声明 `false`；不注册工具、不显示按钮；翻了必须有证据进 `docs/evidence/phase-0.5b/`。
- 测试只用 `node:test`（`node --test --experimental-strip-types`），不引入 vitest/jest；不提交 `.bak`。
- 提交信息中文前缀：`feat: / fix: / test: / docs: / chore:`。

## Review Focus

1. **Claude 回归**：抽 `AgentDriver` 后 `takeover.ts` 的 dispatch/inject/interrupt/handoff/handback 行为必须与 0.5-A 完全一致（229 测试 + 严格 e2e 两轮）。
2. **Codex 运行中 resume**：未验证行为，必须先 cancel 再 resume；超时判 `E_RESUME_REJECTED`，不得静默重试或双写。
3. **Pi 双客户端**：A11 实测 Pi 无锁——第二写者必须 409，且不得在 adapter 层偷偷放行。
4. **未知事件**：三 Agent 的未知记录/坏行只跳过并计数，不抛、不中断整批、不导致 daemon 退出。
5. **假能力**：`GET /agents` 的 caps 必须与实测一致；不支持的 handoff 返回 422 `E_CAP_UNSUPPORTED` 而不是 500。
