## 1. 一页结论

A′ 方向成立，但需要修正两个关键假设：

1. ACP v2 可以作为 Claude/Codex 的统一控制协议：两套官方 adapter 均通过 initialize/new/prompt/list/close/resume 实测。
2. ACP session/list 不能作为“原生会话发现”的唯一来源：Claude 可以列出原生后台会话（cwd 精确匹配，sessionId 与原生一致）；Codex 只列出 ACP 自己创建的会话，codex exec 原生 thread 不在列表里。Codex 原生会话必须从 ~/.codex/sessions/**/rollout-*.jsonl（或 Codex 状态库）发现，再按 thread id 调 session/resume。
3. v1 handoff 的“先 quiesce 再交回”是必要的：Claude 原生会话在后台运行中时，ACP session/resume 会明确拒绝，要求 claude attach 或 claude stop；stop 后 ACP resume 成功，并保留上下文。该行为直接验证了 PRD 决策 11。
4. Windows 上的真 TTY 接管可用：node-pty 1.1.0 + ConPTY 可以启动 claude attach，看到真实 Claude Code TUI，并通过键盘输入注入新 prompt；codex resume 与 pi --session 也能在 ConPTY 中打开真实 TUI。
5. Pi RPC 不是多客户端安全的：两个 pi --mode rpc 进程可以同时打开同一个 session 文件，没有锁；两个进程会各自持有内存状态，写入时产生分支/分叉。控制面必须有 LeaseManager，不能只靠 Pi 自己的 session 文件。
6. DSH 路径暂未验证：系统 Python 没有 windows_mcp 模块，DSH 的 windows-mcp 插件当前 enabled: false；按既定决策，DSH 后置，不阻塞主线。

## 3. 关键细节与修正

### 3.1 Claude：ACP list 能发现原生会话，但运行中不能 resume

claude --bg 创建的后台会话 id 与 ACP session/list 返回的 sessionId 一致。用 cwd=spike/workspace 查询时能同时列出原生后台会话和 ACP 会话；用父目录查询只返回旧会话。说明 cwd 是发现边界。

后台会话运行期间调用 ACP session/resume 会失败：

That session is running in the background (d8c11ae0). Run claude attach d8c11ae0 to open it, or claude stop d8c11ae0 first to resume it here.

执行 claude stop d8c11ae0 后，ACP resume 成功；再 prompt 询问上一轮 token，返回 BG_OK_ACP_CLAUDE_RESUMED，证明上下文保留。

### 3.2 Claude：attach TUI 的 see/inject 可用

用 node-pty 启动 claude attach a9dcf615，捕获到真实 TUI：

- 能看到 Claude Code v2.1.325、cwd、正在执行的 sleep 20 和会话标题；
- 在 TUI 里输入 Reply with exactly ATTACH_INJECT_OK. 并回车，输出 ATTACH_INJECT_OK；
- claude stop a9dcf615 后 claude agents --json 为空。

因此“attach 接管”不是理论假设；v1 可以先 quiesce，再把 TUI 交给用户。

### 3.3 Codex：ACP list 缺失原生会话，但 transcript 与 resume 都存在

codex exec --json 的原生 thread id 为 01a1d7c5-8568-73e2-b75f-ef912b042c4c，原始 transcript：

C:/Users/huang/.codex/sessions/2026/11/14/rollout-2026-11-14T09-56-48-01a1d7c5-8568-73e2-b75f-ef912b042c4c.jsonl

ACP session/list 查 spike/workspace 只返回 01a1d7c5-6010-7a71-ba7d-686a54eedb7c，不返回原生 ...8568。但：

- codex exec resume 01a1d7c5-8568-73e2-b75f-ef912b042c4c ... 成功，返回 NATIVE_OK_RESUMED，thread id 不变；
- ACP session/resume 传入同一个原生 id 也成功，随后 prompt 返回 RESUME_PROMPT_OK。

结论：Codex 的“发现”和“接管”要分开设计。发现走原生 session 文件（或 Codex 状态库）；接管可走 ACP resume，也可走原生 codex resume。不要依赖 ACP session/list 覆盖原生 thread。

### 3.4 Pi：RPC 双客户端没有单 driver 保护

测试用一个持久 session：

E:/pi-workbench/spike/pi-rpc-test2/2026-11-14T02-00-26-491Z_01a1d7c8-d87a-7248-94eb-e14628d41960.jsonl

两个 pi --mode rpc --session <same file> 进程都成功打开，且都报告同一 sessionId。A 在 B 写入后仍显示 messageCount=3，B 已到 5；A 随后基于旧状态追加消息，父节点与 B 的用户消息相同。Pi 的 session 是树形结构，因此不会简单覆盖，但会产生分叉和“两个 driver 各写各的”的状态。

结论：控制面不能把 Pi RPC 当成单写者；LeaseManager 必须在 Pi 路径上强制执行。一个 lease 只允许一个 driver；释放后再 resume/replay。

### 3.5 Windows PTY

- node-pty 1.1.0 安装时 npm 12 拦截了 install scripts，但预编译产物可用；
- pty.spawn('cmd.exe', ...) 输出 PTY_OK；
- claude attach、codex resume、pi --session 都能在 ConPTY 中打开 TUI；
- Codex 需要 TERM=xterm-256color，否则会警告 TERM is set to "dumb" 并要求确认。

### 3.6 当前环境阻塞

Pi 的默认模型 balanced 走 Radius gateway，当前余额为 0：

402 Payment Required: Radius gateway account balance is insufficient: $0.00 available ...

因此 Pi 的 session/state/RPC 控制可以测，但真实 prompt 会失败。这不是控制面协议问题，是账户/模型配置问题；进入 Phase 1 前需要给 Pi 换可用 provider 或充值。

## 4. 对 A′ 方案的影响

1. SessionRegistry 增加 native discovery 层：Claude 用 ACP session/list + ~/.claude/projects/**/*.jsonl 交叉校验；Codex 用 ~/.codex/sessions/**/rollout-*.jsonl 或 Codex 状态库，不把 ACP list 当唯一来源。
2. HandoffManager 维持 v1 quiesce 语义：Claude 运行中先 stop 再 ACP resume；Codex 可直接 native resume，或先停 ACP 再 native TUI；Pi 先释放 lease 再用 pi --session。
3. LeaseManager 不是可选项：Pi RPC 双客户端实测没有锁，且会出现分支。所有 inject/interrupt/handoff 都必须持 lease。
4. PTY adapter 可行：Windows 用 node-pty + ConPTY；attach/resume/pi --session 都能作为“原生终端接管”出口。注意设置 TERM。
5. 能力矩阵要按 agent 分开：Claude 的 list 和 resume 能力不等于 Codex 的 list；Codex 的 resume by id 可用但 list 不可用。UI 按钮应按实测 capability 显示，而不是按统一假设显示。

## 7. 结论

A′ 可以继续，但要把“原生会话发现”和“ACP 会话控制”拆成两层，并把 Pi 的单 driver lease 作为硬约束。当前没有证据支持“所有 agent 都能用 ACP list 发现并接管”；实际是：

- Claude：ACP list + ACP resume（先 quiesce）+ attach TUI；
- Codex：native transcript discovery + ACP resume by id 或 native resume；
- Pi：SDK/RPC + 强制 lease + native pi --session 接管；
- DSH：后置，未验证。
